# ФУФА ТВ: собственная авторизация и favicon

Это исходники сайта и собственного сервиса аккаунтов для Vercel. Регистрация, подтверждение почты, вход, выход, повторная отправка письма и восстановление пароля реализованы здесь. Supabase Auth не используется. PostgreSQL хранит аккаунты и сессии, Resend только доставляет письма.

## Запуск на fufatv.vercel.app

1. Загрузите содержимое этой папки в репозиторий, подключённый к вашему существующему проекту Vercel. Корнем проекта должна быть папка с `package.json`, `vercel.json` и `api`. Загрузка одного HTML не подключит авторизацию.
2. Подключите PostgreSQL, например через Vercel Marketplace. Используйте адрес пула соединений с TLS и проверкой сертификата. Выполните `schema.sql` в SQL-редакторе базы данных. Альтернатива: установить зависимости, задать `DATABASE_URL` в окружении и выполнить `npm run db:migrate`.
3. Подтвердите собственный почтовый домен в Resend и создайте ключ с правом отправки. Адрес вида `accounts@ваш-домен` задаётся в `MAIL_FROM`. Домен `fufatv.vercel.app` сам по себе не даёт почтового домена для отправки писем.
4. В Vercel → Settings → Environment Variables задайте **только серверные** переменные из таблицы ниже. Не вставляйте их в HTML или репозиторий.
5. Framework Preset: **Other**. Команда сборки и выходная папка уже заданы в `vercel.json`. Оставьте автоматическую установку зависимостей: файл `pnpm-lock.yaml` фиксирует версии. Node.js: **22.x**.
6. Выполните Redeploy. Откройте именно `https://fufatv.vercel.app`, зарегистрируйте свою почту, перейдите по письму, задайте окончательный пароль и войдите. Ссылки действуют 30 минут. Пароль — от 12 символов. Проверьте восстановление пароля и выход.

| Переменная | Значение |
| --- | --- |
| `APP_ORIGIN` | `https://fufatv.vercel.app` без завершающего `/` |
| `DATABASE_URL` | Строка подключения PostgreSQL с TLS |
| `RESEND_API_KEY` | Секретный ключ отправки писем |
| `MAIL_FROM` | `ФУФА ТВ <accounts@подтверждённый-домен>` |
| `RATE_LIMIT_SECRET` | Случайный секрет минимум из 32 символов |

Секрет можно получить командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Для Preview используйте отдельную базу и отдельный `APP_ORIGIN`. Запросы с другого адреса блокируются намеренно.

## Что изменилось

- Кислотный знак ФУФА ТВ: SVG, ICO, PNG и иконка для iPhone. Они уже подключены к странице.
- Серверные пароли: scrypt с солью, параметры N=32768, r=8, p=3. Открытые пароли в базу не записываются.
- Сессии на 7 дней в HttpOnly Secure cookie; в базе только хеш токена. Запись в localStorage не даёт доступ к серверу.
- Одноразовые ссылки подтверждения и восстановления; при восстановлении отзываются все сессии. Окончательный пароль задаёт получатель письма, чтобы чужая предварительная регистрация не давала доступ к аккаунту.
- Серверные лимиты запросов по адресу клиента и почте, проверка Origin для изменяющих запросов, параметризованный SQL.
- Кнопки восстановления и повторной отправки письма находятся в форме входа. Для смены аккаунта снова требуется пароль.
- Перед сохранением видео и бонусных треков интерфейс проверяет текущую серверную сессию.

## Границы этой версии

**Сайт ещё не опубликован этой сборкой, база и почта не подключены.** Если настройки отсутствуют, вход показывает ошибку настройки; фиктивного успешного входа нет. Локальное открытие HTML через `file://` не поддерживает серверный вход.

Видео, обложки, плейлисты, профильное оформление, публикации и остальные прежние данные пока остаются в браузере. Старые локальные пароли не импортируются в серверную базу; зарегистрируйте и подтвердите тот же email, чтобы интерфейс сопоставил старые локальные данные. Данные разных доменов и `file://` автоматически не переносятся: используйте существующую резервную копию.

`upload-access` проверяет сессию, но не является облачным хранилищем и не принимает файлы. Владелец браузера технически может изменять своё IndexedDB; клиентский код не может запретить это. Для общей видеоплатформы нужен отдельный серверный каталог и хранилище, где каждый запрос загрузки/изменения вызывает `requireUser` из `lib/auth.cjs` и проверяет владельца по серверному `user.id`. Локальные галочки и нотки не являются серверной верификацией личности.

Подтверждение письма доказывает доступ к почтовому ящику, а не реальное имя человека. Это не аудит всего старого приложения: существующий интерфейс и его сторонние скрипты требуют отдельной проверки перед хранением общих приватных данных.

## Проверки и обслуживание

`npm test` запускает серверные и интерфейсные тесты: гостевой доступ, подмена профиля, cookie, ограничения запросов, подтверждение, повторное использование и истечение ссылок, восстановление пароля, отзыв сессий и смена аккаунтов. PostgreSQL и доставка писем в тестах заменены моделями; перед публичным запуском обязательно пройти шаг 6 с реальной базой и почтовым сервисом. Визуальная проверка сайта в браузере не выполнена.

Периодически удаляйте устаревшие записи SQL-запросами: `DELETE FROM fufa_sessions WHERE expires_at < now();`, `DELETE FROM fufa_tokens WHERE expires_at < now();`, `DELETE FROM fufa_rate_limits WHERE expires_at < now();`. Настройте резервное копирование базы у провайдера. Смена `RATE_LIMIT_SECRET` сбрасывает применимость старых ключей ограничителя.
